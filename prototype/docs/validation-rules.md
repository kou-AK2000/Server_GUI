# チェックルール

## 目的

構成図上の部品、属性、接続情報から、設計時に確認すべき基本的な不足・矛盾を検出するルールを定義します。

この文書はMVP向けのたたき台です。各組織の設計標準、ネットワーク設計、セキュリティ方針に合わせて、後からルール・重要度・警告文を精査します。

## 基本方針

- チェック結果は、保存されたプロジェクトデータから都度計算する。
- チェックは設計上の注意喚起であり、MVPでは保存やCSV出力を禁止しない。
- 値が未入力であることと、値が誤っていることを区別する。
- ルールIDは将来も変えず、画面表示・CSV出力・テンプレートで共通利用する。
- 同じ原因による警告を必要以上に重複表示しない。
- 実際のIPアドレスや顧客名を含むデータでの検証は行わない。

## 重要度

| 値 | 表示 | 意味 | MVPでの扱い |
|---|---|---|---|
| `warning` | 警告 | 設計情報の不足・矛盾。確認が必要。 | 一覧上で目立つ表示をする。保存・出力は可能。 |
| `info` | 情報 | 必ずしも誤りではないが、確認するとよい状態。 | 一覧上で通常表示する。 |

MVPでは `error` や保存阻止は扱いません。実務で必要な必須条件が明確になった段階で追加します。

## チェック結果の共通形式

すべてのルールは、次の形式で結果を返します。

```json
{
  "id": "validation-001",
  "ruleId": "server.ip.duplicate",
  "severity": "warning",
  "message": "IPアドレス 192.168.10.11 がWebサーバー、APサーバーで重複しています。",
  "componentIds": ["server-web-001", "server-app-001"]
}
```

| 項目 | 説明 |
|---|---|
| `id` | チェック実行ごとに生成する結果ID。保存の正本には含めない。 |
| `ruleId` | チェックルールを一意に識別する固定ID。 |
| `severity` | `warning` または `info`。 |
| `message` | 利用者へ表示する説明。 |
| `componentIds` | 関連する部品IDの配列。選択時に対象部品を強調表示するために使う。 |

## MVPのチェックルール

### VR-001: サーバーのホスト名未入力

| 項目 | 内容 |
|---|---|
| ルールID | `server.hostname.required` |
| 重要度 | `warning` |
| 対象 | `Component.type` が `server` の部品 |
| 判定条件 | `serverDetail.hostname` が空文字列または空白だけである。 |
| メッセージ | `［表示名］にホスト名が入力されていません。` |
| 関連部品 | 対象サーバー1件 |
| 除外 | サーバー以外の部品。 |
| CSV出力 | チェック結果一覧に出力する。サーバー一覧のホスト名欄は空欄のままとする。 |

### VR-002: サーバーのIPアドレス未入力

| 項目 | 内容 |
|---|---|
| ルールID | `server.ip.required` |
| 重要度 | `warning` |
| 対象 | `Component.type` が `server` の部品 |
| 判定条件 | `serverDetail.ipAddress` が空文字列または空白だけである。 |
| メッセージ | `［表示名］にIPアドレスが入力されていません。` |
| 関連部品 | 対象サーバー1件 |
| 除外 | サーバー以外の部品。 |
| CSV出力 | チェック結果一覧に出力する。IPアドレス一覧には空欄の行として出力する。 |

### VR-003: IPアドレス重複

| 項目 | 内容 |
|---|---|
| ルールID | `server.ip.duplicate` |
| 重要度 | `warning` |
| 対象 | IPアドレスが入力されたサーバーおよび管理IPアドレスが入力されたネットワーク機器 |
| 判定条件 | 前後の空白を除去したIPアドレス文字列が、2件以上の異なる部品で一致する。 |
| メッセージ | `IPアドレス ［IPアドレス］ が［部品名一覧］で重複しています。` |
| 関連部品 | 同じIPアドレスを持つ全ての部品 |
| 除外 | 空欄のIPアドレス。同じ部品内で同じ値を参照しているだけのケース。 |
| CSV出力 | チェック結果一覧に1つの重複グループとして出力する。 |

MVPでは文字列の完全一致だけを判定します。IPv4形式として正しいか、サブネット内で重複するか、NATやVIPを許容するかは後続フェーズで検討します。

### VR-004: 接続を持たない部品

| 項目 | 内容 |
|---|---|
| ルールID | `component.connection.none` |
| 重要度 | `info` |
| 対象 | 全ての部品 |
| 判定条件 | `connections` に、その部品を接続元または接続先として持つ接続が1件もない。 |
| メッセージ | `［表示名］には接続情報が登録されていません。` |
| 関連部品 | 対象部品1件 |
| 除外 | MVPでは除外しない。将来、外部システム、監視専用、予備機などを除外できるようにする。 |
| CSV出力 | チェック結果一覧に出力する。 |

このルールは未接続が誤りであると断定しないため、重要度を `info` とします。

## 画面上の表示

- チェック結果は、画面下部または右側の一覧パネルに表示する。
- 一覧には重要度、対象、メッセージを表示する。
- 結果を選択すると、関連する部品を構成図上で選択・強調表示する。
- 部品を選択した場合は、その部品に関係する結果を絞り込める。
- 警告数と情報数を件数表示する。

## チェック実行のタイミング

MVPでは次のタイミングで再計算します。

- 部品の属性を保存したとき
- 部品または接続を追加・削除したとき
- プロジェクトを読み込んだとき
- CSVを出力するとき

部品の文字入力中に毎回判定する必要はありません。プロパティ編集の確定時に実行し、操作の妨げにならないようにします。

## MVP後の候補ルール

以下は、MVPの試用で優先度を確認してから追加します。

- IPv4アドレス形式の妥当性
- ホスト名の重複
- ネットワーク機器の管理IPアドレス未入力
- サーバーと接続先のインターフェース重複
- VLAN未設定・VLAN不整合
- OS、ミドルウェア、ポートの必須項目
- ファイアウォール、監視、バックアップの設定漏れ
- サーバー用途と登録ミドルウェアの整合性
- サブネット、デフォルトゲートウェイ、DNSの妥当性
- 組織独自の命名規則と設計標準

## 精査時に確認すること

実際の設計標準へ適用する前に、少なくとも以下を確認します。

1. 警告ではなく保存を禁止すべき項目があるか。
2. VIP、NAT、冗長化構成など、IP重複を許容する例外があるか。
3. ホスト名・IPアドレス・VLANの命名規則をどこまで強制するか。
4. 開発、検証、本番などの環境ごとにルールを変える必要があるか。
5. 設計時と構築後の運用時で、同じルールを使えるか。
