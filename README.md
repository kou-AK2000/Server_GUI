# サーバー構築・設計GUIツール - プロトタイプ

## 目的

サーバー、ネットワーク機器、接続情報、OSなどの設計情報をGUI上で一元管理し、構成図と属性情報の不整合を減らすための検証用プロトタイプです。

本プロトタイプでは、インフラ設計者がExcel、Visio、PowerPointなどへ分散して管理している情報を、ひとつのデータとして扱えるかを検証します。

## このプロトタイプで検証すること

- サーバーやネットワーク機器を構成図へ配置できること
- 機器同士を接続し、接続情報を管理できること
- ホスト名、IPアドレス、OSなどの属性を編集できること
- 全体構成図とサーバー詳細図を行き来できること
- 構成データを保存し、再度読み込めること
- IPアドレス重複や必須項目未入力などの基本チェックを表示できること
- 同じ構成データから、構成一覧やサーバーパラメータシートを出力できること

## このプロトタイプでは扱わないこと

- 実サーバーへの接続、設定変更、Ansibleの実行
- 認証、権限管理、複数人によるリアルタイム編集
- 本番運用を前提とした可用性、監査、バックアップ
- 顧客名、実IPアドレス、認証情報などの機密情報の保存

## 想定する最初の利用シナリオ

1. Web、AP、DBの3台と、ネットワーク機器を構成図に配置する。
2. 各サーバーにホスト名、IPアドレス、OS、CPU、メモリ、ディスクを入力する。
3. サーバーとネットワーク機器を接続する。
4. IPアドレスの重複や必須項目の未入力を確認する。
5. 構成を保存し、再読み込み後も同じ図と属性が表示されることを確認する。
6. サーバー一覧とIPアドレス一覧を出力する。

## 基本方針

- 構成図、属性、接続、チェック、出力は、共通の構成データを唯一の正本として扱う。
- 初期版の保存形式はJSONとする。
- 実データではなく、ダミーの構成データだけを利用する。
- 小さな機能単位で実装・確認を繰り返す。
- 将来の拡張は、プロトタイプの動作確認後に判断する。

## テンプレート拡張の構想

アプリ本体は構成データを管理し、設計書の見た目や章立てはテンプレートで定義できる構成を目指します。

テンプレートには、サーバー、ネットワーク機器、接続、IPアドレス、構成図、チェック結果などを、安定した書き出し用データ仕様（Export Schema）として渡します。組織ごとのExcelやWordの設計書形式は、テンプレート側で吸収できることを目標とします。

初期段階では、任意のプログラムを実行する拡張方式は採用しません。テンプレートの構成、対応する出力形式、データ項目の対応付けを宣言形式で管理します。

## リポジトリの方針

- 仕様、データ構造、テンプレート定義、コードはMarkdown、YAML、JSONなどの差分を確認できる形式で管理します。
- PagesやNumbersは構想メモ・社内説明資料として利用し、設計の正本にはしません。
- 実環境の構成情報、IPアドレス、ホスト名、認証情報、顧客情報は登録・公開しません。
- 将来OSS化する場合も、アプリ本体と組織固有テンプレートは別リポジトリとして管理します。
