# サーバー構築・設計GUIツール（プロトタイプ）

サーバー、ネットワーク機器、接続、サーバー内ミドルウェアを、構成図と共通の設計データとして管理するブラウザアプリです。

## できること

- レベル1：システム全体の構成図を作成・編集
- レベル2〜4：サーバー、アプリケーション／ランタイム、ミドルウェア、パラメータを同じデータとして詳細化
- 部品、接続線、接続先・インターフェース情報の入力
- カスタム部品の追加（名称・アイコン・色）
- ブラウザ内保存、JSON書出し／読込、CSV・Excel出力

## 必要なもの

| 項目 | 要件 |
|---|---|
| OS | macOS、Windows、Linuxのいずれか |
| Node.js | `22.12.0` 以上を推奨（Viteの要件は `20.19.0` 以上、または `22.12.0` 以上） |
| パッケージマネージャー | pnpm 9以降（このリポジトリは `pnpm-lock.yaml` を正とする） |
| ブラウザ | Chrome、Edge、Safari、Firefoxの最新版推奨 |
| ネットワーク | 初回の依存パッケージ取得時のみ必要。起動後の利用はローカルで完結。 |

DB、Docker、クラウドアカウント、環境変数は、現在のプロトタイプには不要です。

## 利用している技術

| 分類 | 採用技術 | 用途 |
|---|---|---|
| 言語 | TypeScript | 設計データと画面ロジックの型安全性 |
| UI | React 19 | ブラウザ画面の構築 |
| 開発・ビルド | Vite 7 | ローカル開発サーバーと本番ビルド |
| 構成図 | React Flow (`@xyflow/react`) | 部品配置、接続、ズームなどのキャンバス操作 |
| アイコン | Font Awesome Free | 部品種別を表すアイコン |
| Excel出力 | ExcelJS | レイアウト画像とレベル別の設計情報を `.xlsx` として生成 |
| 保存 | Browser Local Storage + JSON | 個人の途中保存と共有・バックアップ |

## 初回セットアップ

この `app` ディレクトリで実行します。

```bash
cd app
corepack enable
corepack prepare pnpm@latest --activate
pnpm install --frozen-lockfile
```

`corepack` が使えない場合は、Node.jsの導入方法に合わせてpnpmをインストールしてから、最後のコマンドを実行してください。

## 起動とテスト

```bash
pnpm dev
```

ターミナルに表示されたURL（通常は `http://127.0.0.1:5173/`）をブラウザで開きます。保存済みの内容を確認するには、同じURLを同じブラウザで開いてください。

停止は、起動したターミナルで `Ctrl + C` です。

## 他の人へ渡す場合

渡すものは、原則として次です。

```text
app/
├─ src/               # アプリ本体
├─ package.json       # 使用パッケージ一覧
├─ pnpm-lock.yaml     # バージョン固定された依存関係
├─ vite.config.ts
└─ README.md
```

`node_modules/`、`dist/`、`.pnpm-store/` は渡さず、受け取った人が `pnpm install --frozen-lockfile` を実行します。

## 保存の扱い

- **ブラウザ保存**：そのブラウザ、そのPC、そのURLでの作業用保存です。手軽ですが、他人や別PCとは共有されません。
- **JSON書出し**：システム1件分の構成図・詳細情報をファイルに保存します。共有、バックアップ、Git管理にはこちらを使います。
- **CSV出力**：サーバー一覧・IPアドレス一覧を確認するための出力です。
- **Excel出力**：レベル1〜4を4つのシートに分けて出力します。レベル1の構成図と、サーバーごとのレベル2カテゴリ図をシート上部へ画像として配置し、複数サーバーやサービスの情報は対象レベルの同じシートに集約します。

ブラウザ保存は、ブラウザのサイトデータ削除や、`localhost` のポート変更で見えなくなる場合があります。重要な設計は必ずJSON書出しも保管してください。

## 動作確認コマンド

```bash
pnpm build
```

TypeScriptの型チェックと本番用ファイルのビルドを実行します。

## 現段階で不要なもの

- データベース
- バックエンドAPI
- ユーザー認証
- Docker／Kubernetes
- Terraform／AnsibleなどのIaC実行環境

これらは、複数人同時編集、権限管理、承認フロー、社内サーバーでの常設運用、IaC生成・実行を追加する段階で検討します。
